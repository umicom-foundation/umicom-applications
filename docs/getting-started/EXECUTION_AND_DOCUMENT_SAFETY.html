Framework, Studio and shared trading workflows

1. Check your branch before merging

Run commands one line at a time. Stop if a command reports an error; do not continue with the next directory or publication step.

On Windows:

Set-Location "C:\umicom\Umicom-Applications\framework"
git status
git branch --show-current

On Linux:

cd "$HOME/umicom/Umicom-Applications/framework"
git status
git branch --show-current

If the branch is already main, continue. If the status says detached HEAD and the working tree is clean, compare the checked-out commit with main:

git rev-parse HEAD main

When both hashes match, git switch main attaches to the same source. When they differ, or the detached checkout has unfinished changes, stop and preserve that work before switching. Do not use force checkout, reset or force push to make the message disappear.

Repeat this check in applications/studio and the parent before merging. The publication commands later in the guide assume these checks have been completed. Unrelated clean submodules may stay detached at the parent's recorded revision for building.

2. Configure and build everything on Windows

Use the existing MSYS2 UCRT64 toolchain. Run each command separately and wait for it to finish.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

Configure:

& "C:\msys64\ucrt64\bin\cmake.exe" --preset windows-ucrt64-all-debug -DBUILD_TESTING=ON -DUMICOM_BUILD_NATIVE_TOOL=ON -DUMICOM_BUILD_LEARNING_EXAMPLES=ON -DUMICOM_LEARNING_BUILD_GUI=ON

Build:

& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --parallel 2 -- -k 0

The final build result must succeed. The -k 0 option lets Ninja report additional build failures instead of stopping at the first one; it does not make those failures acceptable. Do not install or publish a failed build.

3. Run focused tests, then the complete Windows suite

The first two commands run this batch's new trading and document cases. The third checks the established Studio and Desk journeys. Each command treats an empty selection as an error.

& "C:\msys64\ucrt64\bin\ctest.exe" --preset windows-ucrt64-all-debug --parallel 1 --no-tests=error --output-on-failure -R '^framework\.trading_execution\.'

& "C:\msys64\ucrt64\bin\ctest.exe" --preset windows-ucrt64-all-debug --parallel 1 --no-tests=error --output-on-failure -R '^framework\.document\.save_target\.'

& "C:\msys64\ucrt64\bin\ctest.exe" --preset windows-ucrt64-all-debug --parallel 1 --no-tests=error --output-on-failure -R '^(studio\.project_workflow|studio\.project_settings\..*|desktop\.launch_lifecycle)$'

After those pass, run everything:

& "C:\msys64\ucrt64\bin\ctest.exe" --preset windows-ucrt64-all-debug --parallel 2 --no-tests=error --output-on-failure

Check the final summary for failures, Not Run, disabled or skipped required tests. A headless service test does not replace the native checks in the next section.

4. Check the applications

Use a disposable Notes project, simulated quotes and test data. Do not use live orders, bank credentials, real payments or production workspaces.

Start Studio from the build directory:

& ".\build\windows-ucrt64-all-debug\bin\umicom-studio-ide.exe"

In Studio, create a small project and edit two source files. Save the first file with Save As and confirm its content and new path. Attempt to save it to the path of the other open file: the save should be rejected, leaving that file unchanged. Close a file chooser with Cancel; it should not display an error. Verify ordinary Save, Save All, build, errors, Run and Install still work.

Where the native chooser permits changing tabs or closing its original document, confirm the save remains attached to that original document; it must never save the new active tab instead. Close Studio with a chooser open and confirm there is no crash or callback into released state. Repeat on both supported desktop platforms.

Close Studio, then start Trader:

& ".\build\windows-ucrt64-all-debug\bin\umicom-trader.exe"

Use Simulation. Preview a market order and inspect its reference price and notional. Change the quantity after preview: Submit must ask for another preview, not submit the old quantity. Check a limit order too. A stale or missing quote must reject market/stop valuation. A preview is only a calculation; submission rechecks the current state. The deterministic simulation remains separate from a real broker connection.

Close Trader before checking Desk and Bank separately:

& ".\build\windows-ucrt64-all-debug\bin\umicom-desk.exe"

& ".\build\windows-ucrt64-all-debug\bin\umicom-bank.exe"

Check launch, normal navigation and shutdown. Do not interpret an unavailable financial action as permission to bypass its service or approval requirements. A zero process exit code alone does not prove these interactions worked.

5. Install a Windows development copy

Close the applications. Use a fresh directory and preserve existing installations. The following creates a unique installation name; it is not a publication script.

Set-Location "C:\umicom\Umicom-Applications"
$Stage = "C:\umicom\installed\execution-document-" + (Get-Date -Format "yyyyMMdd-HHmmss")
& "C:\msys64\ucrt64\bin\cmake.exe" --install ".\build\windows-ucrt64-all-debug" --config Debug --prefix $Stage

Continue only after installation succeeds. Put the installed binaries first and test the installed copy from outside the source tree:

$env:Path = "$Stage\bin;C:\msys64\ucrt64\bin;$env:Path"
& "$Stage\bin\umicom-source-contracts.exe" --help
Set-Location $env:TEMP
& "$Stage\bin\umicom-studio-ide.exe"

Repeat the relevant Studio tests, then start installed Trader, Desk and Bank in turn from $Stage\bin. This development copy still uses your MSYS2 runtime. It is not a demonstrated self-contained installer.

6. Package and deploy a Windows test archive

After qualification, create the archive in a new directory:

Set-Location "C:\umicom\Umicom-Applications"
$PackageDir = "C:\umicom\packages\execution-document-" + (Get-Date -Format "yyyyMMdd-HHmmss")
& "C:\msys64\ucrt64\bin\cpack.exe" --config ".\build\windows-ucrt64-all-debug\CPackConfig.cmake" -G ZIP -C Debug -D CPACK_ARCHIVE_COMPONENT_INSTALL=OFF -B $PackageDir
Get-ChildItem $PackageDir -Filter *.zip

Use File Explorer to extract the resulting ZIP into a new deployment directory. Find its bin directory and repeat the installed-application checks using those executables, not the build-tree copies. Do not deploy over a working installation. Test on a clean target machine before describing the archive as standalone.

7. Linux build, tests, installation and packaging

The example checkout is $HOME/umicom/Umicom-Applications. Use your actual directory if it differs.

For the full native GTK build, the existing project dependencies, including GTK4 development files, must be installed. Configure and build with the established native preset:

cd "$HOME/umicom/Umicom-Applications"
cmake --preset linux-all-gtk4-debug -DBUILD_TESTING=ON -DUMICOM_BUILD_NATIVE_TOOL=ON -DUMICOM_BUILD_LEARNING_EXAMPLES=ON -DUMICOM_LEARNING_BUILD_GUI=ON
cmake --build --preset linux-all-gtk4-debug --parallel 2 -- -k 0

Run focused and full tests, stopping at a failure:

ctest --preset linux-all-gtk4-debug --parallel 1 --no-tests=error --output-on-failure -R '^framework\.trading_execution\.'
ctest --preset linux-all-gtk4-debug --parallel 1 --no-tests=error --output-on-failure -R '^framework\.document\.save_target\.'
ctest --preset linux-all-gtk4-debug --parallel 2 --no-tests=error --output-on-failure

Start each application separately and perform the same interaction checks as Windows:

./build/linux-all-gtk4-debug/bin/umicom-studio-ide
./build/linux-all-gtk4-debug/bin/umicom-trader
./build/linux-all-gtk4-debug/bin/umicom-desk
./build/linux-all-gtk4-debug/bin/umicom-bank

For a build machine without GTK, use the separate headless preset. This validates the service code but does not build the native interface:

cmake --preset linux-gcc-all-headless-debug -DBUILD_TESTING=ON -DUMICOM_BUILD_NATIVE_TOOL=ON -DUMICOM_BUILD_LEARNING_EXAMPLES=ON -DUMICOM_LEARNING_BUILD_GUI=OFF
cmake --build --preset linux-gcc-all-headless-debug --parallel 2
ctest --preset linux-gcc-all-headless-debug --parallel 2 --no-tests=error --output-on-failure

After the native tests and application checks succeed, install without overwriting an earlier copy:

cd "$HOME/umicom/Umicom-Applications"
STAGE="$HOME/umicom/installed/execution-document-$(date +%Y%m%d-%H%M%S)"
cmake --install build/linux-all-gtk4-debug --config Debug --prefix "$STAGE"
"$STAGE/bin/umicom-source-contracts" --help
cd /tmp
"$STAGE/bin/umicom-studio-ide"

Package a native test archive:

cd "$HOME/umicom/Umicom-Applications"
PACKAGE_DIR="$HOME/umicom/packages/execution-document-$(date +%Y%m%d-%H%M%S)"
cpack --config build/linux-all-gtk4-debug/CPackConfig.cmake -G TGZ -C Debug -D CPACK_ARCHIVE_COMPONENT_INSTALL=OFF -B "$PACKAGE_DIR"
ls "$PACKAGE_DIR"

Extract into a new directory and test that copy. Packaging does not prove that all system dependencies are bundled.

9. Parent repository — publish last

Only continue after all changed child repositories have been committed and pushed. First update the native repository lock.

Windows:

Set-Location "C:\umicom\Umicom-Applications"
git status
git switch main
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& ".\build\windows-ucrt64-all-debug\bin\umicom.exe" repo lock .

After the lock succeeds:

git add -A
git diff --cached --check
git diff --cached --submodule=log
git commit -m "chore(applications): integrate execution and document safety updates"
git push --recurse-submodules=check origin main
git status

Linux, using the native build:

cd "$HOME/umicom/Umicom-Applications"
git status
git switch main
./build/linux-all-gtk4-debug/bin/umicom repo lock .

For a headless-only build, use the existing ./build/linux-gcc-all-headless-debug/bin/umicom instead. After the lock succeeds:

git add -A
git diff --cached --check
git diff --cached --submodule=log
git commit -m "chore(applications): integrate execution and document safety updates"
git push --recurse-submodules=check origin main
git status

The final status should be clean when no other work remains. The parent push checks publication of the submodule commits; it does not compile, test or upload uncommitted child files.

11. Final inspection

From the parent directory, inspect the parent and children. This is a read-only Git command, not an automatic publication script.

git status
git submodule foreach --recursive 'git status --short --branch'

A clean receiving checkout can have detached submodules at the parent's recorded revision. That is normal. Do not change all child revisions merely to remove the detached message. A push of main publishes that branch, not an unrelated detached commit.

The existing Git lesson in framework/docs/learning explains cloning the complete project and updating a second machine to the parent's recorded revisions. Keep receiving worktrees clean before git pull --ff-only and git submodule update --init --recursive; those commands are not a method of publishing local edits.

12. Qualification limits

The supplied validation report lists the Linux builds and tests actually run for this batch. Windows execution and native GTK compilation/interaction were not available in the preparation environment. The GTK changes are source-reviewed and require sections 2–7 on the supported native machines before release.

The quote policy is a development risk estimate, not live-trading certification. Current account scope, currency conversion, business-day loss boundaries, aggregate working orders, durable execution replay and broker reconciliation remain separate work. No live orders or real payments are part of these checks.
